# T-6.13 — E6 : décodage AR en Core AI à états (optionnel, décidé à G-9)

Jalon : 6 · Prérequis : réponse G-9 « E6 : oui » · Tier : 2 · ⛔ GATE : non

## Objectif
Savoir si un modèle Core AI **à états** (cache KV mis à jour en place, deux fonctions `prefill`/`decode`, moteur GPU pipeliné) décode plus vite que MLX int4 sur l'iPhone, à parité greedy 8/8.

- `plan/13-ios-backend.md` §13.3 ligne « Décodage AR » ; recette Llama d'Apple (int4 + états : https://machinelearning.apple.com/research/core-ml-on-device-llama) ; `reference/…` : recette Qwen3 du dépôt `apple/coreai-models` si présente (`uv run coreai.model.registry --list-models`)
- `Sources/YuE2Core/Generation/TokenGenerator+CFG.swift` (187 lignes)

## Fichiers à créer
- `Scripts/coreai/export_ar_stateful.py` : module PyTorch autour de `YuE2ForCausalLM` upstream, voie AR seule : `register_buffer` `k_cache`/`v_cache [28, 1, 8, CTX, 128]`, `forward(ids [1, N], positions)` avec écriture en place (`index_put`/`slice_scatter`), deux fonctions d'un même asset : `prefill` (N dynamique) et `decode` (N = 1) ; **deux têtes** : `logits_abc` (lignes `[0, EOD) ∪ {ABC_END}`) et `logits_semantic` (`[CODEC_OFFSET, +32768) ∪ {MUSIC_END}`) en sorties séparées (ou deux fonctions `decode_abc`/`decode_semantic` partageant les poids) ; CTX ∈ {2048, 4096} énuméré ; `coreai_opt.presets.w4`.
- `Sources/YuE2Core/CoreAI/CoreAIARDecoder.swift` : `InferenceFunction.MutableViews` pour les états, boucle de décodage branchée sur `LogitsProcessor` (espace local, inchangé), CFG non supporté (mode `off` exclu, `guidance == 1`).
- `yue2 parity lm --backend coreai-gpu` (greedy 8/8, rel) ; `yue2 bench-coreai-ar` (tok/s vs MLX).
