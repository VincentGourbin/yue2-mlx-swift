# T-6.3 — E3 : décodeur (et encodeur) VAE en Core AI, GPU et Neural Engine

Jalon : 6 · Prérequis : T-6.1 (fp16 accepté) · Tier : 2 · ⛔ GATE : non

## Objectif
Un `.aimodel` fp16 du décodeur Oobleck à formes énumérées, exact vs MLX fp32 (SNR > 40 dB), compilé pour GPU **et** pour Neural Engine, mesuré sur le Mac ; le protocole `VAEDecoding` avec repli MLX. **Jamais de spécialisation CPU** (défaut ouvert de la conv transposée sur CPU pour noyau ≥ 8 : nos noyaux 12/10/8 sont concernés).

## Fichiers à créer
- `Scripts/coreai/requirements.txt` : `coreai-torch==0.4.2`, `coreai-core==1.0.0b2`, `coreai-optimization` (version constatée), installés dans `.venv-ref` par `uv pip install --python .venv-ref/bin/python -r Scripts/coreai/requirements.txt`.
- `Scripts/coreai/export_vae.py` : charge `YuE2VAE.from_pretrained(models_dir/"YuE2-Vae", device="cpu")` upstream ; **fusionne weight-norm** (`torch.nn.utils.remove_weight_norm` sur chaque conv) ; `eval()` ; `.half()` ; `torch.export.export(decoder, (z,), dynamic_shapes={"z": {2: torch.export.Dim("T", min=288, max=1056)}})` (si l'export dynamique échoue : trois programmes à formes fixes 288/544/1056 ajoutés au même asset par `add_exported_program`, noms `decode288`…) ; `TorchConverter().add_exported_program(ep, input_names=["z"], output_names=["audio"]).to_coreai()` ; `optimize()` ; `save_asset(models_dir/"YuE2-Vae/coreai/YuE2VaeDecoder.aimodel")` ; idem encodeur ; vérification Python avec le runtime `coreai` (`AIModel.load`, fonction `main`) : SNR et cosinus vs PyTorch fp32 sur `latent_40` → `COREAI VAE OK snr=<dB> cos=<x>`.
- `Scripts/coreai/compile.sh <asset> <iOS|macOS> <gpu|neural-engine>` : `xcrun coreai-build compile … --platform … --preferred-compute … --output …` ; les artefacts `.aimodelc` vont sous `$YUE2_MODELS_DIR/…/coreai/` (gitignoré).
- `Sources/YuE2Core/Backends/VAEDecoding.swift` (protocole + conformance `YuE2VAE`).
- `Sources/YuE2Core/CoreAI/NDArrayBridge.swift` : `MLXArray` ↔ `NDArray` (fp16/fp32, `mutableView`/`view`), `#if canImport(CoreAI)`.
- `Sources/YuE2Core/CoreAI/CoreAIVAEDecoder.swift` : `AIModel(contentsOf:)` (asset ou `.aimodelc`), `loadFunction(named:)`, `preferredComputeUnitKind` selon `.coreaiGPU|.coreaiANE`, forme ≥ tuile, pad droit, crop, sortie fp32 NLC ; erreur ⇒ repli MLX journalisé.
- `DecodeCommand --vae-backend mlx|coreai-gpu|coreai-ane` ; `ParityCommand --backend …` : `PARITY vae_coreai: snr=<dB> cos=<x> ms_per_tile=<ms> units=<gpu|ane>`.
- `Tests/YuE2Tests/CoreAIVAETests.swift` (tier 2, gardé par l'existence de l'asset) : SNR > 40 dB sur `latent_40` ; tuilé 1100 == MLX fp32 à SNR > 40 dB, pour les deux placements.

## Étapes
1. Installer, exporter, vérifier en Python. 2. Compiler `gpu` et `neural-engine` pour macOS. 3. Swift, parité, latences par tuile (288/544/1056) × placement, `docs/knowledge/log.md`. 4. Compiler aussi pour iOS (assets prêts pour T-6.5). Commit `feat(coreai): VAE decoder/encoder assets and backend (E3)`.

## Validation
1. `bash -c '.venv-ref/bin/python Scripts/coreai/export_vae.py --models-dir "$YUE2_MODELS_DIR" | tail -1'` → `COREAI VAE OK snr=… cos=…`
2. `Scripts/check-build.sh` → `BUILD OK`
3. `bash -c 'for u in coreai-gpu coreai-ane; do .xcodebuild/Build/Products/Release/yue2 parity vae --backend $u --models-dir "$YUE2_MODELS_DIR" | tail -1; done'` → deux lignes `PARITY OK vae …`
4. `Scripts/check-tests.sh CoreAIVAETests` → `TESTS OK (≥ 4 tests, 0 skippés)`

## Critère de fin
Validations vertes ; tableau latence (tuile × placement × MLX) consigné. Si l'ANE échoue à la parité mais pas le GPU : consigner et poursuivre avec GPU.

## Réouverture (2026-09-21, hors fiche, demande de Vincent : « n'écarte pas cette piste »)
La dégradation tuilée (33,75 dB) venait du **zéro-padding des latents** vers la forme énumérée, pas de Core AI : `planVAETiles` (`VAEDecoding.swift`) élargit chaque fenêtre à une forme exacte au lieu de compléter. `yue2 parity vae --backend coreai-gpu` → `snr=54,7 dB` (pire tuile 53,3, pire couture 54,9), tuiles 1024 et 256, **`PARITY OK`**. Le GPU Core AI est donc valide pour le VAE (option C de fait) ; ANE inchangé (impasse `coreai-torch 0.4.2`). Mesures mémoire/temps dans `docs/knowledge/log.md` (2026-09-21). `yue2 generate --vae-backend coreai-gpu` branche ce backend dans le pipeline.
