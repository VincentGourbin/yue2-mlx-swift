# T-1.5 — Tokenizer : conversion `tokenizer.json` + `YuE2Tokenizer` Swift

Jalon : 1 · Prérequis : T-1.3, T-1.4 · Tier : 2 · ⛔ GATE : non

## Objectif
Encoder exactement comme `qwen.tiktoken` (NFC, sans tokens spéciaux) via swift-transformers et un `tokenizer.json` dérivé de Qwen2.5 dont `added_tokens` est vidé.

## À lire
- `plan/02.7-tokenizer.md`
- `reference/flux-2/Sources/FluxTextEncoders/Tokenizer/TekkenTokenizer.swift` lignes 220-260 (`AutoTokenizer.from(modelFolder:)` en situation) — le fichier `Gemma4TokenizerLoader.swift` cité par le plan n'existe plus dans gemma-4
- `reference/yue/src/yue2/tokenization_yue2.py` lignes 1-41

## Fichiers à créer
- `Scripts/convert-tokenizer.py` : lit `$YUE2_MODELS_DIR/YuE2-3B/tokenizer.json.qwen25` (ou le télécharge), vide `added_tokens` (liste vide), met `post_processor` à `null`, garde `normalizer` NFC, écrit `$YUE2_MODELS_DIR/YuE2-3B/tokenizer.json` ; puis vérifie avec `tokenizers` que chaque texte de `parity/tokenizer_corpus.json` donne les mêmes ids que tiktoken (charge `qwen.tiktoken` comme upstream) ; sort `TOKENIZER OK <n textes>` ou `TOKENIZER MISMATCH` + premier écart.
- `Sources/YuE2Core/Tokenizer/YuE2Tokenizer.swift` : `public final class YuE2Tokenizer: TextEncoding, @unchecked Sendable` ; `static func load(modelDir: URL) async throws` (`AutoTokenizer.from(modelFolder:)`) ; `encode(_ text:)` = `precomposedStringWithCanonicalMapping` puis `tokenizer.encode(text:addSpecialTokens: false)` ; `decode(_ ids: [Int])` ne garde que `0 ≤ id < YuE2Token.eod` ; `precondition` au chargement : `encode("<|endoftext|>")` ne contient pas 151643 (sinon `added_tokens` non vidé).
- `Tests/YuE2Tests/TokenizerTests.swift` (tier 2, `.enabled(if:)` sur `YUE2_MODELS_DIR` + existence de `YuE2-3B/tokenizer.json`) : corpus complet identique ; round-trip decode/encode sur 3 textes ; aucun id ≥ 151643.
