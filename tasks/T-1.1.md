# T-1.1 — Environnement Python de référence + pytest upstream

Jalon : 1 · Prérequis : T-1.0 · Tier : 1 · ⛔ GATE : non

## Objectif
`.venv-ref` avec les versions épinglées par upstream, le paquet `yue2` installé depuis `reference/yue`, et les tests upstream verts : c'est la source de vérité des fixtures.

## À lire
- `Scripts/setup-reference-env.sh` (30 lignes, déjà fourni)
- `reference/yue/pyproject.toml` lignes 1-30 (versions)

## Fichiers à créer / modifier
- `docs/knowledge/log.md` : une ligne « référence Python : upstream <sha>, torch 2.10.0, transformers 4.57.6, pytest upstream vert (n tests) ».

## Étapes
1. `Scripts/link-references.sh` (crée `reference/`, clone YuE si absent) — vérifier que `reference/yue/src/yue2/modeling_yue2.py` existe (`ls reference/yue/src/yue2`).
2. `Scripts/setup-reference-env.sh` (peut durer 5-10 min : téléchargement de torch). Dernière ligne attendue : `REFERENCE ENV OK — upstream <sha>`.
3. Si pytest échoue sur un test réseau/Hub (`test_cli_public`, `test_skill_*`), relancer avec `-k "not cli_public and not skill"` et noter la limite dans le journal ; si un test `test_model`/`test_nar`/`test_vae` échoue : STOP, `tasks/ASK.md`.
4. Ajouter la ligne au `docs/knowledge/log.md` ; commit `chore: reference python env`.

## Validation
1. `bash -c '.venv-ref/bin/python -c "import torch, transformers, tiktoken, yue2; print(torch.__version__, transformers.__version__)"'` → `2.10.0 4.57.6`
2. `bash -c 'cd reference/yue && ../../.venv-ref/bin/python -m pytest tests/test_model.py tests/test_nar.py tests/test_vae.py tests/test_protocol.py -q 2>&1 | tail -1'` → une ligne se terminant par `passed`

## Critère de fin
