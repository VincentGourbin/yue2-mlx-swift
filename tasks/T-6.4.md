## Fichiers à créer
- `Scripts/coreai/export_nar_stack.py` : module PyTorch `NARStack(nn.Module)` construit à partir de `YuE2ForCausalLM` upstream (bf16 → fp16) : `forward(x_t [L,64], t_shifted [1], k_ar [28, L_ar, 8, 128], v_ar [28, L_ar, 8, 128]) -> v [L,64]` reproduisant `velocity` (padding START/END, `vae2llm`, time embedder, `pe` recalculé, par couche : norme, projections, q/k-norm, RoPE avec offset L_ar (positions passées en entrée), `cat` K/V, SDPA sans masque, `o_proj`, MLP ; norme finale, `llm2vae`). `dynamic_shapes` : L ∈ Dim(256…2048) et L_ar ∈ Dim(256…8192) si l'export passe ; sinon buckets L ∈ {256, 512, 1024, 1536, 2048} × L_ar paliers de 512 avec masque booléen des clés de padding. **int8** sur les poids linéaires (`coreai_opt` preset int8, EAGER) — pas `w4` : E2 a montré que le 4 bits sur la voie NAR sort du budget de parité (l'erreur se compose sur 64 évaluations) ; les activations restent fp16. Vérification Python : `velocity_raw{20,0,-2.3}` de `$YUE2_MODELS_DIR/parity/nar.safetensors` → rel < 5e-2 ; `coreai.save_intermediates` pour le Debugger si écart.
- `Sources/YuE2Core/Backends/NARVelocityBackend.swift` ; `CoreAI/CoreAINARStack.swift` : conversion du cache `KVCache` MLX en deux `NDArray` **une fois par chunk**, bucket, padding/masque, appel par évaluation, sortie `MLXArray` ; `CachedNAR` accepte un `NARVelocityBackend`.
- `Sources/YuE2CLI/BenchCoreAICommand.swift` : `yue2 bench-coreai-nar --frames 256,512,1024,1536 --backends mlx,coreai-gpu,coreai-ane` : 20 itérations par forme, ms par évaluation, ms de conversion K/V, extrapolation `64 × ms` vs NAR MLX mesuré ; ligne finale `E4 VERDICT: mlx=<s> gpu=<s> ane=<s>`.
