### 2.4 Étape NAR — flow matching (`nar.py`)

Entrées : `prefix` (préfixe sémantique complet, cf. §2.1), `codec` (tokens sémantiques, T frames), `seed`, `steps = 32`.

1. **Découpage** (`chunk_ranges`) : `size = min((24576 - len(prefix) - 3) // 2, 24576)` ; chunks `[a, min(a+size, T))` pour `a = 0, size, 2·size…`. En pratique **un seul chunk** (prefix ≈ 1-6 k tokens ⇒ size ≥ 9 000 ≥ max_tokens). Le code doit néanmoins gérer N chunks (boucle série).
2. **Bruit** : `noise = randn((T, 64), fp32, seed)` tiré **une fois** pour toute la chanson, puis découpé par chunk. (Le RNG PyTorch n'est pas reproductible en MLX : `MLXRandom.normal` seedé côté Swift ; pour les tests de parité, le bruit est **injecté** depuis la fixture.)
3. Par chunk `[a, b)` : `ar_tokens = prefix + [CODEC_OFFSET + c for c in codec[a:b]] + [MUSIC_END]` (longueur `L_ar`), `L_nar = (b - a) + 2`. Contrainte `L_ar + L_nar ≤ 24576`.
4. **Prefill AR** (`_prefill`) : voie AR, attention causale, positions RoPE `0..L_ar-1`. On conserve par couche `(K, V)` **après q/k-norm et RoPE** — `[L_ar, 8, 128]` chacun. (`nar_cond_end` est toujours 0 dans le pipeline ⇒ tout le préfixe est visible.)
5. **Vitesse** `velocity(state [T_c, 64] bf16, raw_t)` :
   - `x_nar = [0-row ; state ; 0-row]` → `[L_nar, 64]` ; `x = vae2llm(x_nar)` (les lignes nulles reçoivent le biais) ;
   - `t_sig = sigmoid(bf16(raw_t))` (**sigmoid calculée en bf16**), `t_shift = shift·t_sig / (1 + (shift-1)·t_sig)` = `t_sig` (shift = 1.0) ;
   - `x += time_embedder(t_shift)` (même vecteur pour toutes les positions : sinus 256-d calculé en fp32 : `freqs = exp(-ln(10000)·arange(128)/128)`, `emb = [cos(t·freqs), sin(t·freqs)]` → cast bf16 → MLP) ;
   - `x += latent_pos_embed.pe[0 .. L_nar-1]` (positions **locales**, clampées à 24575) ;
   - positions RoPE des tokens NAR : `L_ar .. L_ar + L_nar - 1` ⇒ `MLXFast.RoPE(offset: L_ar)` ;
   - pour chaque couche : `q,k,v = nar_self_attn.project_qkv(nar_input_layernorm(x))` ; `K = concat(K_ar, k)`, `V = concat(V_ar, v)` ; attention **sans masque** (les NAR voient tout le préfixe AR et tous les NAR, bidirectionnel) ; `x += nar_self_attn.o_proj(h)` ; `x += nar_mlp(nar_pre_mlp_layernorm(x))` ;
   - sortie `llm2vae(norm(x))[1 : -1]` → `[T_c, 64]`.
6. **Solveur midpoint** (`solve`) : `state = noise.to(bf16)`, `dt = 1/steps` ; pour `k = 0..steps-1` : `t = 1 - k·dt` ; `raw = clamp(logit(t), -20, 20)` (calculé en **float64**, `logit(1) = +inf → 20`) ; `v1 = velocity(state, raw)` ; `mid = state - v1·dt/2` ; `raw_mid = clamp(logit(t - dt/2), -20, 20)` ; `state = state - velocity(mid, raw_mid)·dt`. **Tout en bf16** (state, v, produits). 64 appels de `velocity` par chunk. Résultat concaténé → fp32 `[T, 64]` ; erreur si non fini.
7. Coût : chaque `velocity` = forward complet de la voie NAR sur `L_nar` tokens (≈ 5 400 pour 3,6 min) avec attention sur `L_ar + L_nar` clés (≈ 12 800). C'est **l'étape dominante** sur Mac (§3).
